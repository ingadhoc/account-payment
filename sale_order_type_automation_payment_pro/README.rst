===========================================
Sale Order Type Automation - Payment Pro
===========================================

Bridge module between ``sale_order_type_automation`` and ``account_payment_pro``:
makes the sale order type automatic payment reconcile against the invoice created
by the flow instead of the partner's prior debt.

Features
========

- When a ``sale.order.type`` automates invoice creation and its payment
  (``payment_atomation = validate_payment``) on a company with ``account_payment_pro``
  enabled (``use_payment_pro = True``), the automatic payment is scoped to the invoice
  generated by the automation.
- Prevents ``account_payment_pro`` from loading the partner's whole open debt and
  reconciling an older invoice instead of the one created by the flow.
- Installs automatically (``auto_install``) only when both base modules coexist; both
  are left untouched.

Technical Details
=================

- New models: none.
- Inherited models: ``account.move``.
- Override of ``_prepare_dict_account_payment``: adds ``to_pay_move_line_ids`` to the
  payment values, set to the invoice open lines (``invoice.open_move_line_ids``).
  Passing the field explicitly in ``create`` makes the ORM skip
  ``account.payment._compute_to_pay_move_lines`` for that record (same mechanism as
  ``account.move.pay_now()``), so ``_add_all()`` does not replace the lines with the
  partner's full debt.
- Views: none.
- Data / security: none.

Usage
=====

1. Install ``sale_order_type_automation`` and ``account_payment_pro``; this module
   installs on its own when both are present.
2. Enable ``account_payment_pro`` on the company (``use_payment_pro``).
3. Configure a sale order type (``sale.order.type``) with
   ``payment_atomation = validate_payment`` and its payment journal.
4. Confirm a sale of that type: the automation creates and validates the invoice,
   registers the payment and reconciles it against that invoice, leaving any prior
   partner debt untouched.

Architecture
============

The module contributes a single override on ``account.move`` in
``models/account_move.py``. It extends, via ``super()``, the
``_prepare_dict_account_payment`` method defined by ``sale_order_type_automation``,
injecting the to-pay line scope that ``account_payment_pro`` reads. It defines no
models, views or data of its own: all the automation and payment business logic stays
in the base modules.

Dependencies
============

- ``sale_order_type_automation``
- ``account_payment_pro``
